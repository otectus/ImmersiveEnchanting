# Immersive Enchanting - Forge 1.20.1 Mod

## Orientation
Registration inventory and package layout live in `MODMAP.md` (generated by `.mcmod-tools/modmap.py`). Read that
instead of crawling `src/`. The design brief is `docs/Immersive_Enchanting_Forge_1.20.1_Development_Spec.md`;
config, datapack formats, commands and the Java API are documented in `README.md`.

## Quick Reference
- **Mod ID**: `immersive_enchanting`
- **Package**: `com.otectus.immersiveenchanting`
- **MC / Loader / Java / compat mod ids**: see `gradle.properties`
- **Mappings**: official
- **Protocol versions**: `ModNetwork.VERSION` (packets), `PatternGenerator.VERSION` (generated patterns)

Version numbers live only in `gradle.properties`; `processResources` expands them into `mods.toml`.

## Build
- `.mcmod-tools/gradlew-quiet.sh <dir> compileJava` - compile only
- `... build` - reobfuscated jar in `build/libs/`; also runs the JUnit suite (`src/test`, pure ritual math)
- `... runGameTestServer` - GameTests (`src/gameTest`, template `immersive_enchanting:empty`, test datapack namespace
  `ie_test`); exits non-zero on failure. Sessions follow game time there (`SessionClock`), since the test server fast-forwards
- `... runClient -PsmokeTest` - smoke agent (`src/smokeTest`): flat survival world, a real table, offers clicked through
  Forge's input path, rituals played with key events; `run/screenshots/smoketest_*.png`, `run/smoketest/smoketest-result.json`
- add `-PcompatMods=apotheosis -PsmokeExpect=apotheosis` (or `easymagic`) to run the agent against the real mod
- `python3 tools/generate_sounds.py` rebuilds the synthesized sounds; `tools/generate_logo.py` the logo

## Structure
```
ritual/     pure, deterministic, no Minecraft imports: PRNG, motifs, generator, validator, score engine,
            difficulty, arcane value, downgrade resolver. Shared by client and server; unit-tested
api/        public SPI (EnchantingContextAdapter), value records, RitualPlanEvent / RitualResultEvent
enchanting/ adapter registry, vanilla adapter, offer planner, ritual policy, button guard
session/    server sessions (RitualSessionManager), effects, offer previews, Forge-bus wiring
data/       datapack enchantment profiles and pattern sets (reload listeners, precedence)
network/    packets and codecs;  command/  operator debug commands
client/     everything client-only: controller, screen hooks, renderer (client/render), practice screen
compat/     easymagic (matched by class name), apotheosis (compileOnly; reflection for two private members)
mixin/      EnchantmentMenu accessor + invoker, removed() hook, button-packet guard; client/ button-packet intercept
```

## Conventions
- The enchanting system decides what is rolled: capture its own plan (the invoker), never reimplement selection.
  Adapters apply by mirroring their system's own click method with the resolved list.
- Server authoritative: clients send the offer index and key inputs only, never a score, plan or item.
- Client code is reached only through `DistExecutor` or `Dist.CLIENT` subscribers; common code never imports `client/`.
- Optional mods are loaded only by `CompatibilityBootstrap` (class name, after a `ModList` check).
- Config: `ServerConfig` (SERVER, synced; the client reads its switches to decide interception) and `ClientConfig`.
- Player-facing text is always a translation key in `assets/immersive_enchanting/lang/en_us.json`.
- Any change to motifs or the generator changes patterns: bump `PatternGenerator.VERSION` and `ModNetwork.VERSION`.

## Terminology
- plan: the enchantments the table would apply for an offer; primary binding: the offer's clue enchantment
- complexity 0-100 gives the tier (Initiate..Arcane); the ritual score 0-100 gives the band (Perfect..Shattered)
